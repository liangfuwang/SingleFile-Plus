# SingleFile Plus 网页存档 — Chrome 插件

把网页一键保存为**单文件 HTML**：图片 base64 内嵌、离线可看、点击放大。抓取方式自动判断，无需手动选择：

- **静态抓取** —— 直接请求服务端返回的 HTML，适合 Discuz 论坛帖等传统服务端渲染页面（自动处理登录 Cookie、年龄门、懒加载、分页）
- **渲染抓取** —— 在真实标签页里执行 JS、滚动触发懒加载后取渲染完的 DOM，适合飞书文档 / Notion 等 SPA
- **判定依据**：已知 SPA 站点（飞书/Notion/语雀/知识星球）直接渲染；其余先静态请求一次，正文是空壳（如 `<app-root>` / `#root` 里没内容）、请求失败、或同 URL 标签页里的真实文本远多于静态文本，就走渲染，否则走静态。日志里会写明依据

## 安装（一次性）

1. 打开 Chrome，地址栏输入 `chrome://extensions/`
2. 右上角打开 **开发者模式**
3. 点左上角 **加载已解压的扩展程序**
4. 选择本目录 `~/VibeCoding/SingleFile-Plus/extension`
5. （可选）点浏览器右上角拼图图标 🧩，把「SingleFile Plus 网页存档」钉到工具栏

## 使用

1. 先在浏览器里**登录**目标站点（Cookie 会被插件自动使用）
2. 打开想保存的帖子页（也可以不打，直接在插件里粘贴 URL）
3. 点工具栏插件图标 → 弹窗自动填好：
   - **页面 URL**：自动取当前标签页，也可手动粘贴
   - **文件名**：自动取自帖子完整主题（含 `[原创]` 这类主题分类，`【】[]` 等括号原样保留，只去掉 Discuz 后缀和不可见字符），可随意修改；不改就按抓到的页面自动命名
4. 点 **「保存为单文件 HTML」**。任务在后台运行，可以直接关闭弹窗、切到别的标签页；图标角标 `…` 进行中 / `✓` 完成 / `✗` 失败，重新打开弹窗可看到日志
5. 文件出现在**下载文件夹**：图片全部 base64 内嵌 + 点击放大灯箱，离线永久可看

## 功能

- 自动处理：登录 Cookie、18+ 年龄确认门、Discuz 懒加载（`zoomfile`/`file` 真实地址）、帖子分页（多页合并为一个文件）
- 样式表自动内嵌为 `<style>`，页面脚本全部移除，本地打开无 JS 报错
- 自定义头像 403 时自动回退站内默认头像；实在拿不到的图片用内联占位图替换，不留外部请求
- 防盗链绕过：插件用 `declarativeNetRequest` 临时给图片请求注入 Referer，下载完自动删除规则
- 兜底校验：检测到图片被 302 重定向到占位图会判为失败并提示，不会把"被盗"占位图存进文件
- **后台保存**：抓取流水线跑在 offscreen 文档里，由 Service Worker 调度，与弹窗和当前标签页无关；同一时间只跑一个任务
- **渲染抓取**：优先复用已打开的同 URL 标签页；没有就后台新开一个（不会抢焦点），抓完自动关掉。渲染抓取需要那个标签页保持存在到抓取结束（约几十秒），期间别关它；后台标签页定时器会被浏览器降频，长文档会慢一些
- **长评论与滚动上限**：渲染抓取会自动展开折叠回复、全文和「加载更多」入口；到底后回滚检查至少 3 次，无加载提示且页面高度、正文内容稳定后结束。知识星球的「评论加载中...」和动画加载状态会继续等待；到底后 60 秒没有加载进展、滚动受阻、达到 6000 轮或 10 分钟上限时，会明确警告可能没抓全，HTML 顶部也会保留提示
- **文件名兜底**：Chrome 对下载文件名有严格校验（首尾不能是空白/./~、不能含 `..`、不能是 Windows 保留名），文件名被拒时自动换 `web-时间戳` 重试，不会因为标题里有奇怪字符整条失败

## 技术说明

- MV3 插件：`popup.js` 只管界面；`background.js`（Service Worker）调度任务并代办特权操作（标签页抓取、Referer 规则、下载）；`rendered-capture.js` 提供可独立测试的标签页采集函数；`offscreen.js` 跑抓取 / 内嵌图片 / 生成文件的主流程；`common.js` 放文件名处理
- 插件页面 fetch 拥有 `<all_urls>` host 权限，跨域抓图片不受 CORS 限制
- 渲染抓取用 `chrome.scripting.executeScript` 注入目标标签页，逻辑完全自包含；完成底部与加载状态检查后才序列化 DOM。HTML 中的 `singlefile-plus-capture` 元数据保留停止原因、主评论数及底部检查次数，方便核对
- 纯原生 JS，无任何外部依赖

## 常见问题

- **图片全部下载失败** → 确认浏览器已登录站点；换个帖子重试；把弹窗日志发给维护者
- **文件名不满意** → 弹窗里直接改
- **飞书文档报「没取到渲染后的 DOM」** → 一般是没登录被跳到了 `accounts.feishu.cn` 登录页。先在浏览器里登录飞书、打开该文档确认能看到正文，再点保存
- **飞书文档提示「疑似虚拟滚动」** → 页面只在 DOM 里保留可视区域的块，超长文档可能缺内容。可以先在飞书里把文档导出为 Word 再处理
- **渲染抓取保存下来包含飞书侧边栏/顶栏** → 这是按「保存整个页面」抓的，和页面长得一样；如果只想要正文，反馈一下再加「只保留正文」开关
- **离线打开时图标/字体缺失** → 页面 DOM 里的图片已经全部 base64 内嵌；但样式表内部的 `url()`（飞书的字体、图标）仍是外链，离线时回退。这是为控制体积有意为之
- **想存到指定位置** → 把 `popup.js` 里 `saveAs: false` 改成 `true`，每次保存会弹另存为对话框

## 长评论采集回归测试

在项目根目录运行 `python3 -m http.server 8765 --bind 127.0.0.1`，用 Chrome 打开 `http://127.0.0.1:8765/tests/rendered-capture.html`，点「运行回归测试」。测试使用实际采集函数，覆盖慢分页文本提示、动画加载提示、首屏无滚动条的延迟加载、嵌套滚动与不可见侧栏、加载卡住五个场景，同时检查折叠回复能展开、跳转链接不会误点。

测试时保持测试标签页在前台；后台计时器降频会导致测试超时。也可用 Node 24+ 运行相同场景的 DOM 模拟测试（不启动浏览器）：`npm --prefix tests install --ignore-scripts`，然后 `npm --prefix tests test`。模拟测试还覆盖滚动无法推进的告警；真实站点的最终完整性仍需在登录状态下另行核对。
